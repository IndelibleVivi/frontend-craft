**状态：方向已确认，待实施规格。** 本文提交不表示下列工具、实例或接续行为已经实现，也不表示任何新风格已经获得用户审美认可。

- 规格日期：2026-10-08（Asia/Singapore）；本次修订明确 repertoire、材料记忆与 showcase 的不同交付。
- 审查基线：[`f128df124da0d5c6a961f600ae50128028714f62`](https://github.com/IndelibleVivi/frontend-craft/tree/f128df124da0d5c6a961f600ae50128028714f62)。
- 范围：让 FC 在普通前端制作与修改中，能够发现、看见、使用、保留并继续加工有用的视觉实例与材料。
- 本文是这项工作的单一主规格。后续实现计划引用第 12 节的覆盖 ID；实施顺序可以调整，完整交付范围继续保留。

## 1. 要兑现的结果

用户说“帮我把这个前端做好看一些”后，FC 应能结合真实内容、项目已有语言和当前偏好，提出并做出有具体视觉品质的完整结果。用户不必先当参考研究员、字体管理员、提示词翻译员或实验主持人。

本轮补齐四项相连的制作能力，并以独立 showcase 展示实际表现力：

1. **正向制作积累。** Styles、Palette、Elements combinations 三个入口连接可看的作品、已实践的制作关系和可用于生产的材料。优秀外部作品、公开实现与教程可以提供研究依据；实际复现或应用后再记录相应的 practiced slot。
2. **项目 Reference Gallery。** 保留代理真正看过的参考、当前试用的关系和实际项目结果；下一次工作能打开原物，继续判断。
3. **材料接续。** 找回准确的字体、原图、生成图、纹理、程序图形和衍生产物，知道在哪里使用、怎样继续加工。
4. **普通入口接通。** 这些能力由 FC 在制作、修订、取得材料和交接时主动使用；已有记忆继续影响决定，并保持反馈范围。

**Showcase 的职责是展示设计与制作的表现力。** 它可以反过来贡献可复用的 slot，但不由功能测试类别自动生成创作命题。参考库、材料库、制作实例与展示作品共享准确来源和关系，各自按实际作用判断完成。

用户应直接感受到：首次结果有更具体的构图与材料；修改能保留真正奏效的部分；换任务、换会话后不用重新贴研究结果。技术验收能核对这些动作是否发生，审美判断仍需要实际看页面。不能把工具运行成功折算成“已经变好看”。

## 2. 仓库审查：哪些节点尚未长成能力

本次检查覆盖当前全部 70 个受跟踪文件的目录结构、19 个方法参考、入口、辅助脚本、示例与相关测试、维护要求和近期历史。以下结论限于上述公开快照。未检查私人记忆目录、实际宿主安装或用户本地项目；没有把未出现在远端的会话日志当作仓库事实。

| 节点 | 现有源码已经表达的内容 | 当前缺口 | 对应交付 |
|---|---|---|---|
| 正向 repertoire | [style-slots](../../references/style-slots.md) 允许完整体验、视觉语言、局部组合和具体技法，并要求实例、材料和变化条件 | 正式条目只有两项，均指向同一 Liquid Matter 路由；没有相应规模的可选实例库 | V1、V2 |
| 项目参考 | [design-direction](../../references/design-direction.md) 要求查看真实参考与状态；[build](../../references/build.md) 要求保留选中物并在制作中重访 | 没有项目集合、截图/材料登记、画廊生成或采用关系的实际实现 | V3、V4 |
| 材料生产与复用 | [SKILL](../../SKILL.md)、[visual-construction](../../references/visual-construction.md) 已包括字体、图像、纹理、代码图形、空间与动效 | 没有材料索引、已取得文件的解析、原物与衍生关系、使用位置及恢复路径 | V5 |
| 字体、配色与组合 | [reference-sources](../../references/reference-sources.md) 有六条条件化制作路线；banner 源码有实际配色 | 制作路线主要是文字；没有实际加载字体的中英样张、用于真实场景的配色实例或成套组合 | V1、V2、V5 |
| 构图余地 | 方法明确要求从内容和任务组织整体，避免反复套同一排列 | 可复用实践覆盖的问题很少；变换配色或同一渲染器的对象不能扩充成新的构图家族 | V2 |
| 记忆影响下一步 | [design-learning](../../references/design-learning.md)、[memory-operations](../../references/memory-operations.md) 和 `fc_memory.py` 已支持有范围的案例 | 案例 CLI 处理文字记录，不解析字体、截图、生成图或项目中采用的版本；取回文字不保证实际看见视觉材料 | V4、V5、V6 |
| 跨宿主与自然调用 | 维护要求已区分源码、安装、执行、接受；`agents/openai.yaml` 提供入口提示 | 没有证据表明两个实际宿主读取了相同当前记录并能解析同一材料 | V6、V7 |
| 日常效果证据 | 有示例、行为案例菜单、记忆/存储检查 | 现有测试未验证“普通请求发现材料、做进项目、下次继续用”这条完整路线 | V7 |

几个审查边界必须保持准确：

- [showcase](../../examples/showcase/README.md) 的商店、刊物、线场确实有不同构图；本规格不声称所有旧示例结构完全相同。Liquid Matter 的多个对象属于同一个渲染系统。
- 旧条目的机制价值与用户审美接受分别保留。不能通过重新命名、迁移目录或截图包装，把研究候选和旧机制升级为已认可风格。
- 最近的 [`f128df1`](https://github.com/IndelibleVivi/frontend-craft/commit/f128df124da0d5c6a961f600ae50128028714f62) 修改了两个 README、SKILL、design-learning 和 QA 的文字，未增加辅助工具或示例运行能力。它强化了已有意图，材料与接续缺口仍然存在。
- [`test_examples.py`](../../tests/test_examples.py) 检查合成记忆数据；[behavior-cases](../../references/behavior-cases.md) 是案例菜单。它们不提供一般审美质量或自然调用效果的通过证据。

**设计判断：现有方法已经足以指导大量正确动作，下一步应把这些动作所需的对象、材料和调用路线补齐。** 本规格不继续增加一套平行的设计原则层。

## 3. 普通制作中怎样工作

### 3.1 什么时候介入

| 当前任务 | 代理应做的工作 | 用户额外负担 |
|---|---|---|
| 新建重要界面、整体美化、明显构图不合适 | 读取实际项目与相关偏好；查询相关实例和已有项目参考；打开有用原物，形成制作选择并实现请求范围 | 无需先组织 moodboard 或主持风格投票 |
| 清楚的局部修复 | 读取受影响的当前采用关系和材料；有需要才扩展调查 | 不强制重新找一轮风格 |
| 下载、生成、裁切、子集化或实际采用关键材料 | 从真实工具结果登记原物、衍生物和来源；更新项目采用位置 | 不要求用户复制文件名、补标签或确认每次登记 |
| 收到有意义的反馈 | 按既有学习规则保存范围合适的案例，指向确切实例；更新真正变化的当前采用关系 | 自然反馈即可；不要求打星、填写表单 |
| 继续旧项目、换会话或宿主 | 先找现有画廊、当前使用材料和相关案例，解析文件，再继续修改 | 不要求重贴字体清单、参考链接或上次样张 |

查询与查看的数量由实际不确定性决定。一个清楚的已选方向可以直接继续；有结构性分歧时才打开有辨别力的不同参考。不得为每个任务固定要求三个方向、指定数量的外站或先做一轮对照实验。

### 3.2 一条完整的正常路线

以下阅读项目仅用于解释调用与接续，题材不指定首个实例或 showcase 的创作方向：

1. 用户要求让阅读页更有性格，并保留已认可的题字。代理找到实际当前页、题字对应字体文件与旧反馈。
2. 代理打开与当前问题相关的实际作品，查看正文与窄屏状态；同时回看项目中保存的原参考。外部研究与已实践的 slot 分别标明，判断适合借用的关系。
3. 代理用项目正文试排，必要时获取或制作材料。选中的关系例如“正文连续阅读，边注贴近当前段落”；引用保持在具体范围。
4. 代理完成请求涉及的页面和行为，在真实运行页面检查题字、字体回退、内容密度、注释与返回位置。
5. 项目画廊显示原参考、实际采用的关系和当前结果。关键字体原文件、投产版本与生成方式可解析；案例保留局部反馈。
6. 下一次标题新增字符，代理能回到同一字体版本重建受影响的子集，并查看新页面。用户不需要重新解释来源。

画廊在这条路线中提供制作现场和记忆入口。它不成为完成页面之前必须向用户汇报的新阶段。

## 4. 正向实例库：三个入口，同一批真实作品

“正向”表示作者有意做成并愿意作为具体制作目标供人查看的实例。它不自动表示用户喜欢，也不表示适用于所有项目。库中需要可执行实例；外部发现指针、生成概念图和方法研究另外标明证据性质。

### 4.1 Styles

Styles 展示一套视觉语言在实际内容与使用中的样子。一个条目至少包括：

- 足够看清整体层级的初始画面，以及一个会改变布局或注意力分配的工作状态。
- 实际文字长度、所声称支持的文字体系、图像或图形、控件及相关动效。
- 能运行或重放的实例、实现入口和实际材料。
- 适合的内容与目的，哪些关系应保留，哪些部分可以变化，一项具体失配条件。

完整构图可以直接复用；也允许只取一个有用关系。名称如 editorial、archive、playful 可以辅助检索，但不能代替作品本身。

### 4.2 Palette

Palette 从**已在实例中成立的颜色关系**进入：底、抬升面、主次文字、强调色及其前景、选择态和必要状态反馈。条目要在真实画面里显示面积、相邻关系和密度变化。

色值与可复制 token 是交付的一部分，主预览应显示颜色如何承担角色。不得把一排 HEX 当作完整配色实例，也不设通用 60/30/10 比例。

同一配色可以连接多个真正做出来的场景。库不自动生成所有 palette × layout 组合；没有实际检查的搭配不能借其他实例的证据进入正向入口。

### 4.3 Elements combinations

这里保存的是共同工作的关系，例如：

- 标题字形、安静的注释与对齐数值共同建立层级。
- 图像裁切留下的空处、标题位置与贴边图说相互约束。
- 集合中的选中物、展开详情和返回过程保留来源位置。
- 鲜明作品、平静工具区、可读数值和选择反馈共同支持编辑。

每个组合说明：谁主导，其他部分怎样支持，哪些变量需要一起调整，在哪些内容或状态下会失配。一个漂亮按钮、一种纹理或一个字体名可以作为材料进入目录；成为 combination 需要呈现它与其他部分的实际关系。

### 4.4 每份可用实例的交付包

一个实例包应包含可运行作品、代表性真实内容、预览、制作说明、实现源与材料指针。索引存放用于查询和展示的简短事实；较长说明留在实例旁。不要在索引、README 和方法文档中复制三份相同规则。

| 内容 | 最低要求 |
|---|---|
| 可看 | 整体及有意义的工作状态；宽窄视图足以判断所声称的行为 |
| 可拿 | 准确源文件、材料、配色 token、实现入口和必要生产步骤 |
| 可改 | 固定关系、可变部分、真实内容替换入口；关键依赖有说明 |
| 可判断 | 已渲染、已操作、仅静态观察或仍为候选等证据明确；反馈按实际范围链接 |
| 可继续 | 源材料和投产变体有稳定身份；前后版本不会覆盖到无法辨认 |

类型宣称需要实际支持：中文实例必须使用真实中文、标点、混排、数字及合理长度，并确认字体文件实际加载。CSS 写了某个 family 名称不足以证明字体呈现；一种字体可得也不足以证明适合当前长正文。

### 4.5 先建立可进入制作的 repertoire

积累的单位由实际作品和制作问题决定，不规定先原创六份页面来填充目录。初始内容可以来自有出处的优秀外部作品、公开实现、作者教程，以及本地实际做成的作品。代理需要查看原物，说明值得借取的具体关系，再取得有权使用的材料或实现。

| 对象 | 可进入目录的内容 | 怎样继续使用 |
|---|---|---|
| 外部参考与研究 | 实际页面、工作状态、图像、样张或教程；来源和观察条件 | 形成有根据的制作假设；访问权不自动赋予素材或代码复用权 |
| 生产材料 | 准确字体、图像、程序图形、可复用代码及许可，必要的原物与衍生版本 | 直接取得、放进目标并继续加工；材料可用不等于其所有旧用法获认可 |
| Practiced style slot | 已在实际作品中做出的效果、运行或重放入口、实现、材料与变化条件 | 保留成功关系，按目标内容改造；实践与认可各有具体范围 |
| Showcase | 有明确创作追求、鲜明表现力和完整体验的可运行作品 | 展示能力，研究制作过程，并提炼有价值的 slot |

正向输入需要在字体骨架与排法、图像/材质处理、空间权重、色彩面积或时间组织上带来实质不同的选择。不要以换色、重复构图、条目数或下载量宣称 repertoire 已丰富。中文制作须有实际中文材料和试排；不能用英文参考的气质替代中文执行。

一份有用的研究不必先变成独立 demo。一个 slot 也不必负担整站功能。首轮从能改变当前制作决定的作品开始，做进完整目标，再留下可复现的效果与材料；既不止于链接收藏，也不把弱作品包装成正向库存。

### 4.6 Showcase：以创作追求组织的完整作品

Showcase 用于展示高完成度的设计与制作能力。排印、构图、图形、材料、空间、动效和交互都可以成为表达的核心；复杂技术本身不构成好作品。每份作品要能说清想让人看见或体验什么，并以真实画面和使用过程兑现。虚构题材标为作者实例，不伪称真实组织或用户作品；作品承诺的交互、保存与结果必须实际完成。

- 先选择有辨识度的创作问题与实际可看的目标，取得或制作决定性材料，在 renderer 中解决最影响作品成败的部分，再扩展完整体验。
- 成品应具有清楚的整体身份、主导关系和精细执行。需要多个工作状态或宽窄布局时，表达与使用都应成立，不能只保住入口截图。
- 实际源文件、材料、运行方式与关键制作手段可追溯；从作品提炼 slot 时明确哪些关系值得保留、哪些条件下需要重做。
- 当前任务的审美方向和禁区直接影响题材与手段选择；不把一轮偏好固化为整个公共 FC 的永久皮肤。
- 渲染、行为测试、创作判断、用户接受与自主 FC 效果分别报告。形式数量或测试通过不能替代作品的表现力。

阅读与边注、集合与详情、空间导航、对象编辑、内容展开、比较与执行仍可用作行为覆盖的场景菜单。按实际作品的使用过程选择和检查，不要求每类各造一份 demo，不将这些类别作为 showcase 的固定创作 brief。

## 5. Reference + Assets 的范围与寻找方向

Reference 指可再次查看并产生判断的依据；Assets 指可进入生产或继续加工的材料。同一对象可以具有两种角色。原物应保留比首次解释更丰富的信息，便于后来发现新的关系。

| 媒介 | 参考可能教会什么 | 可接入制作的材料 |
|---|---|---|
| 网站、应用与运行状态 | 注意力组织、信息密度、展开次序、路径与反馈 | 可复用代码在许可允许时另行取得；截图本身通常只充当参考 |
| 字体、字样与排印 | 字形气质、中文比例、混排、字距、标题与正文关系 | 准确字体版本、许可文件、字重/轴、网页变体、子集和生产脚本 |
| 摄影、插画、艺术作品 | 裁切、色彩面积、节奏、媒介质感 | 有相应使用依据的原图、透明层、裁切与响应式变体 |
| 纹理、符号、图标、程序图形 | 材料密度、边缘、局部识别与图文关系 | 原文件、可编辑源、参数、导出文件 |
| 动效、视频、声音 | 次序、连续性、响应、声音在交互中的角色 | 实際可播放材料、关键帧或实现、时长/循环/播放条件 |
| 生图概念与生产图 | 风格、构图、纹理、对象形态的可见探索 | 实际输出、提示与参考关系、尺寸、透明信息、衍生物 |

默认发现入口优先公开可访问的完整站点、作者/工作室作品、开放教程与源代码、字体作者与官方发行、具有明确访问条件的艺术/馆藏资料。具体方向由问题决定：

- 组织阅读与内容：刊物、图书与档案呈现、公共文化机构、长期内容站。
- 形成材料与色彩：摄影系列、插画、艺术家 portfolio、公开艺术社区、材料和印刷样本。
- 增加空间与时间表现：互动作品、开放创意前端教程、可运行作品及其制作记录。
- 选择文字：字体作者样张与正式文件，尤其观察实际文字体系和目标内容。
- 支持日常操作：公开可运行的软件与有状态示例，实际查看集合、详情、编辑、错误和返回。

公开艺术社区可以用于发现；逐项区分能看、能获取和能用于当前产品。不要把平台名当作统一的资产使用许可。默认路线不依赖付费或封闭 UI 参考库。当前已经授权且可用的其他来源可按任务使用，不扩写成永久的价格禁令。

查询词可组合“内容/行为问题 + 媒介或时期 + 具体形式”，如“长文 边注 字体样张”“collection detail return animation”“植物档案 展签 排印”。先取得少量有区别的实际内容；模糊风格词命中大量重复首页时应换方向。

## 6. 项目 Gallery 的具体产品行为

### 6.1 屏幕应该回答什么

首次打开应直接看见当前项目正在参考和采用的东西。画廊至少提供：

1. **项目与当前表面。** 能到达实际项目预览、当前采用项及其位置。项目设计入口已有说明时链接回去。
2. **当前视觉材料。** 大到能辨认层级的预览、简短采用关系和状态。候选与使用中清楚区分；不会先展示很长的流程解释。
3. **条目详情。** 全图、截图状态或播放片段、原始出处、实际文件/实例入口、制作说明、项目使用关联。
4. **相关历史。** 被替换的参考、旧捕获与早期结果折叠可回看。当前内容明显，历史仍保留确切版本。

默认优先当前项目的实际采用和近期相关候选。检索或筛选可按语言、媒介、任务、Styles/Palette/Combinations 和来源缩小范围；无需先完成筛选才能看到作品。

不同媒介采用合适的预览：整页截图能放大查看，长图不永久压进统一裁切卡片；动效保留关键状态序列或视频；字体使用真实字样；音频使用真实播放入口和可辨认说明。动图与声音不默认同时自动播放。

### 6.2 V1 的交互边界

V1 是可重建的静态只读画廊。代理通过文件和辅助工具维护目录，用户可浏览、搜索/筛选、打开全图与原站、进入实例或项目使用位置，并回到原列表状态。

页面不要放置未实现的 Adopt、Apply、Save 或生成按钮。“已用于”必须来自登记并核对过的项目关系。复制条目 ID 可作为便利操作，不能成为用户必须手工传递参考的步骤。

可用性检查覆盖键盘、焦点、宽窄布局、长名称、缺失文件、空结果和返回位置。图像按需加载并保留比例；在详情可看足够分辨率的原捕获。元数据和使用关系在媒体失败时仍能阅读。

### 6.3 捕获与版本

代理使用宿主已经可用且符合当前权限的浏览、截图、下载或图像工具取得材料。`fc_catalog` 接收真实结果，V1 不捆绑另一个通用浏览器或后台监控器。

捕获最少保留来源、取得时间、实际文件与可辨认说明。页面截图在适用时记录 viewport、整面或裁切、状态；交互证据记录做过的动作及结果。不能从静态截图推断已操作，也不能把生成概念图标成实际网站截图。

外站改版或材料变更时新增版本。旧来源 URL 可以相同，旧像素和反馈不能被新画面悄悄替换。只保存会影响判断和接续的节点，不要求归档每次滚动截图。

### 6.4 真正进入代理视觉上下文

目录查询先返回有界元数据和可打开位置；影响构图的候选随后必须通过宿主实际图像/页面能力打开。画廊生成成功、路径存在或收到 JSON 都不能代替这一步。

代理再查看项目实际结果，判断采用的关系是否真的出现。相关参考与项目捕获可以并列，必要解释直接附在采用项上。接口不可用时记录具体缺口，并继续可完成的工作；不得声称已经视觉检查。

## 7. 数据归属与最小目录契约

### 7.1 保留现有事实来源

| 位置 | 唯一职责 |
|---|---|
| 项目源码和已有设计入口 | 当前实现、当前产品决定；目录中的使用声明需由它们核对 |
| 私人 `context.md` | 当前偏好、愿望与边界，遵循现有读取规则 |
| 私人 `cases.json` v1 | 有范围的反馈、观察、假设及其生命周期 |
| 新可视目录 | 对象身份、视觉原物、材料位置、制作关系、版本、来源 |
| 项目目录中的 `uses` | 哪个对象的哪个关系被选作何用、是否已在实际项目中出现 |
| 生成的 Gallery | 上述目录的可视读法；删除后可重建 |
| 随包制作积累 | 有来源的研究入口、按条款可分发的材料与独立实例；不带私人反馈档案 |

本轮保留 `cases.json` v1 和 Cloudflare 索引字段，不迁移所有案例。案例现有 evidence 可以指向稳定目录条目及其版本；私人画廊可以链接案例 ID。反馈正文和当前偏好不另存一份 profile。

材料的可发现范围独立于评价范围。现有 `--transfer` 只放宽案例的 project，surface 约束继续存在；寻找旧字体不得借机修改这些范围。Cloudflare 是派生案例索引，不同步本地案例正文或二进制材料。

### 7.2 放在哪里

- **公开实例：** 提议 `examples/library/`，含 `catalog.json`、实际参考的来源/观察记录、已实践实例的实现/说明/预览和按条款可分发的材料。外部参考与本地作品按证据区分，不默认打包第三方原图或代码。与现有 showcase 分开，避免改写旧证据。
- **项目集合：** 优先使用项目已有、适合当前隐私范围的设计工作位置；否则采用项目本地 `.frontend-craft/catalog.json` 与 `.frontend-craft/gallery/`。代理设置本地忽略，并从既有设计入口或任务交接留下可发现指针。私人截图和记录不因目录在项目内就自动提交。
- **可跨项目材料：** 使用已明确授权的私人 FC 位置中的材料目录。尚未配置时先保留项目内可用条目，不扫描全盘、聊天历史或所有下载。
- **目标产品资产：** 按项目惯例放入真正的生产位置，保留来源与目录引用。目录不强迫产品从私人路径加载，也不重复拷贝整套实例库。

三类集合使用同一格式与辅助工具。它们通过稳定引用相连；不要求把同一份字体复制到三个数据库中。指定目录可以重复传入查询；同一集合 ID 映射到不同目录时应报歧义，不能任取其一。

### 7.3 V1 结构

新增 `scripts/fc_catalog.py` 负责目录验证、查询、解析、登记与静态生成。默认采用 Python 标准库完成元数据与 HTML 工作，不新增常驻服务或必需语义索引。宿主继续负责实际观看、取得与生成媒介。

顶层结构为 `version`、`id`、`revision`、`items`、`uses`：

- `version: 1` 是格式版本。
- `id` 为稳定集合 ID，`revision` 为整个文件的单调修订号。
- `items` 保存条目版本；`uses` 保存项目采用关系版本。二者以 `(id, revision)` 唯一。
- 同一 ID 的最高修订为当前版本；历史版本保留。可选 `archived: true` 只影响默认发现，不使精确历史引用失效。
- 跨集合引用采用 `{catalog_id, item_id, revision}`，精确资产再加 `asset_id`，精确预览则加 `preview_id`；后二者互斥。绝对文件路径不是身份。

条目按角色填写，避免让一张外部截图承担整份实现规格：

| 字段 | 规则 |
|---|---|
| `id`, `revision`, `title`, `roles` | 所有条目必需；roles 可包含 `reference`, `material`, `style`, `palette`, `combination`，允许重叠 |
| `source` | 来源类别 `authored` / `external` / `generated`，适用的 URL、作者、版本、原始条目引用；来源与使用权分别描述 |
| `tags` | 少量任务、媒介、语言、尺度维度；用于检索，不能替代视觉 |
| `previews` | 媒体 ID、类型、locator、实际文件摘要；适用时包含 capture 条件、时间、viewport、状态、裁切或序列 |
| `specimen` | 正向实例的运行入口、源文件和较长制作说明 locator；外部参考可以只有原站与捕获 |
| `making` | 作为正向实例时必需：`effect`, `carry`, `vary`, `limits`，简述作用、应保留关系、可变项与限制 |
| `palette` | palette 角色必需：实际角色和值、前景/背景配对、对应实例与状态；面积说明仅描述该实例 |
| `assets` | 实际原物与生产变体，含稳定资产 ID、locator、文件类型、已取得文件的 SHA-256；仅远端来源不伪造本地摘要 |
| `materials` | 关联材料的稳定引用；字体、图像等无需在每个 style 中复制 |
| `derivation` | 需要继续加工的产物指向确切源资产、已有脚本/说明和输入依赖；存下的命令不由 resolver 自动执行 |
| `rights` | 已查看的来源/许可位置与取得条件；未知则明确未知，不推导再分发授权 |
| `evidence` | 已查看/渲染/操作的条件与对应捕获，或精确的私人案例引用；不新增统一 `approved` 字段 |

源码的实际 JSON 校验应按角色检查最低有效载荷、ID/修订引用和 locator。字段新增需同格式兼容；未知格式版本给出明确错误，不猜测并改写。

locator 使用 `{root, path}`：`catalog` 表示该目录文件的同级根，`project` 表示明确提供的项目根，其余 root 由显式宿主参数绑定。非 `catalog` 的根绑定以集合 ID 为作用域，避免同时查看两个项目时错用同一个 `project`。路径为相对路径；解析后的真实路径必须位于指定根内。允许多个授权根，拒绝绝对路径冒充可移植记录、路径穿越和意外符号链接外逸。

本地截图、取得的二进制材料及衍生物在登记时计算真实摘要。可编辑的活源码入口允许没有固定摘要；关联已观察结果时记录对应源码修订或工作副本说明。不得让一个变化中的实现入口冒充历史捕获。

一般关联允许成环，例如实例连接配色，配色再连接实例。查询和 `show` 只展开有界直接关系，按稳定引用去重，深层内容按需读取。`derivation` 的生产依赖必须无环，源资产必须有精确版本；缺少外部集合时保留 unresolved，不能宣称依赖已验证。

### 7.5 使用事实与评价事实

使用记录包括 `id`、`revision`、目标 project/surface/location、稳定对象引用、`relation`、`status` 及核对依据。`status` 为：

- `selected`：当前打算采用或正在试用，尚未核实真正进入目标。
- `in-use`：已核对实际源码/渲染的使用，记录时间及对应依据。
- `past`：已被替换的采用关系，历史仍可回看。

一个关系可同时引用多个材料。`location` 指可定位的路由、文件、组件或区域，不强迫每个项目生成新的设计文档。`in-use` 始终表示某次核对时的观察，画廊显示对应依据和时间，不宣称实时状态。再次进入项目或依赖该关系修改时，代理对照当前源码；发现替换则登记新版本，不引入任意天数的自动过期规则。

下载事实来自真实取得结果；文件当前是否可用来自解析；使用事实来自项目；喜欢或拒绝来自案例。允许“下载了没用”“用了但整体不满意”“只认可题字”“整体被替换但字体仍有用”。这些情况不能压成 found → downloaded → adopted → approved 的单线状态。

## 8. CLI、写入与恢复

以下为提议接口，实施应保持其行为语义。命令帮助、文档和调用示例必须同步，不留虚构可执行命令。

```text
python scripts/fc_catalog.py query --catalog <path> --with-catalog <dependency> --role <role> --language <tag> --term <text> --limit 12
python scripts/fc_catalog.py show --catalog <path> --id <id> [--revision <n>]
python scripts/fc_catalog.py resolve --catalog <path> --id <id> [--revision <n>]
python scripts/fc_catalog.py register --catalog <path> --record-file <json> --expect-revision <n>
python scripts/fc_catalog.py validate --catalog <path>
python scripts/fc_catalog.py gallery --catalog <path> --out <path> [--view-bindings <json>]
```

所有命令共用以下输入：一个 `--catalog` 主目录，零个或多个只读 `--with-catalog <path>` 依赖目录，以及可重复的 `--root <catalog-id>:<alias>=<path>`。`catalog` 根从文件位置得出，不可重绑；`project` 与其他根显式绑定，例如 `--root sample-reader-project:project=/work/sample-reader`。这些参数由已知项目/私人入口取得，不能变成用户的路径搜集作业。

`show/resolve` 的 ID 属于主目录；关联从已传入依赖中解析。`register` 只写主目录。`query` 可搜索主目录与依赖；`gallery` 以主目录的项目项为主，只呈现其实际引用的依赖材料，不把整个私人材料库摊进项目画廊。`validate` 验证主目录与可解析的跨集合引用。

过滤项和依赖项均为可选项，示例同时列出以说明能力。查询至少支持 role、task、language、medium 和文字项；按集合 ID、条目 ID 进行确定性排序兜底，相关当前采用关系可优先展示。分页使用有界 `--offset` / `--limit`，返回 `next_offset` 与本次查询各集合修订；翻页前目录变化时提示重新查询，不拼出伪一致结果。不依靠用户点击次数自动推断偏好。

| 命令 | 契约 |
|---|---|
| `query` | 只读；默认查各 ID 当前未归档版本；返回稳定引用、简短关系、实际预览/原物入口和 `matched/returned/truncated`；提供实际可用的 continuation 参数 |
| `show` | 读取一个当前或指定历史版本、关联材料与使用位置；不声称已观看文件 |
| `resolve` | 按 locator 检查当前文件与摘要；逐资产返回 `available`, `missing`, `changed`, `remote-only` 或 `unavailable`、实际位置和可恢复来源；不自动下载/上传 |
| `register` | 接收真实工具结果整理出的条目/使用关系输入或完整版本导入；校验、并发检查、原子写入；返回实际写入 ID 和新修订号 |
| `validate` | 检查格式、角色必需数据、修订唯一、引用与 locator；区分结构错误和当前缺失材料，不能用简单通过隐藏缺失 |
| `gallery` | 从明确输入生成可重建 HTML/媒体视图；不更新 context 或 cases，不对外发布 |

外部集合未传入时，跨集合引用应返回 `unresolved-catalog` 及所需集合 ID；不在任意磁盘位置试探。`resolve` 缺失单一衍生物时仍返回其他可用原物。

### 8.1 登记输入与并发

`record-file` 包含集合 ID、本次条目/使用关系的输入。代理提供稳定 ID、角色、真实来源、文件输入位置、用途及必要关联；helper 从实际文件取得摘要、类型和状态，并分配下一整数修订。允许导入完整版本，但必须核对其事实与修订。不得要求代理或用户手写这些可计算事实。

新建集合时 `--expect-revision 0`；目录不存在与已有目录为空不同。旧版本不就地覆写。重复输入按语义和实际内容摘要比较，自动生成的登记时间和修订号不应制造重复记录。删除私人记录按用户明确范围另行处理，历史保留规则不能阻止实际删除请求。

**先留存实际文件，再公布引用。** `register` 负责把需保留的截图、样张和难以忠实重做的生成原物从输入位置归入主目录的不可变媒体位置，再写目录。采用内容摘要命名并去重，例如 `media/sha256/<digest>.png`；导入时可提供 `input_locator`，登记结果返回正式 `locator` 与摘要。已有可验证、可回看的确切版本可以直接引用；一般生产文件仍可链接并报告当前变化，不一律复制。

不可变位置已有同摘要文件时核对并复用，绝不覆盖不同内容。图像工具重复写 `screenshot.png` 不会改变早先已经留存的捕获。媒体准备失败则不发布声称已留存的新版本；登记中断可能留下未被引用的文件，但不能破坏旧引用。清理仅作用于确定无引用的派生文件，原始材料与私人记录删除继承用户具体范围。

同一目录默认由主代理协调写入，子代理返回变更。实现仍须保护真实并发：

1. 使用覆盖“读取 → 核对修订 → 验证 → 写临时文件 → 原子替换”的本地排他锁。只有 revision 检查加 rename 无法防止同时通过检查的写入。
2. 等锁有界；失败返回 `busy`，不永久挂起。不能仅凭锁文件年龄删除一个可能仍活跃的锁。可使用操作系统锁及平台适配，退出由系统释放。
3. 预期修订陈旧则返回 `conflict` 和当前修订，保持原文件。代理重读后可以合并不同 ID 的新增；同 ID 冲突必须理解当前改动后协调。
4. 完全相同的已登记版本重复提交返回 `unchanged`。只有整个提交中的内容都已一致存在时，才允许在陈旧预期修订下做此幂等返回。
5. 文件写入失败保留上一个完整目录；临时文件不作为当前目录读取。跨 checkout 冲突沿已有 Git/私人同步解决，不引入分布式锁。

机器可读结果用稳定的 `ok/status`、具体对象和原因。操作失败退出非零；某文件缺失可以返回可读的部分结果，但必须明确 partial，不得伪报全部完成。

### 8.2 画廊生成与隐私

- 生成使用独立暂存输出，只复制实际引用的预览/播放媒体到输出内的去重目录，并用相对 URL 和媒体清单呈现。即使目录、来源材料和输出分处不同授权根，正式浏览入口也必须能显示它们。媒体准备完成后最后替换入口；中断时上一次可读输出继续存在。没有有效媒体的条目仍显示缺口及来源。
- 可运行 specimen 使用由当前宿主实际启动/核实的 HTTP(S) 入口；通过 `--view-bindings` 传入稳定条目/使用引用到当前 URL 的映射。该文件是本地运行绑定，不取代 canonical locator；不复制整个应用或全部私人目录。不具备运行入口时给出可解析源码、已检查的启动说明和“尚未运行”状态，不能生成看似可点的坏链接。正式 A3 验收须启动实际入口并打开成功。
- 仅渲染转义后的元数据；不执行外站 HTML、目录里的脚本字符串或任意 SVG 活动内容。外部链接只接受普通 `https` 与适用的 `http`，拒绝 `javascript` 等活动协议；本地媒体使用生成的相对 URL。外部素材以安全图片/媒体展示或链接打开，作者实例走其独立运行入口。
- 生成页面默认在本地查看；不自动复制私人案例正文、凭据、宿主绝对路径或无关材料。公开包中的原始实例与项目私人画廊维持独立范围。
- 项目材料取得、生成、对外共享继承当前任务与宿主权限。索引登记不另外要求逐条批准，也不扩张实际工具权限。
- 可用的本地服务/浏览能力用于查看运行实例；启动方式明确且输出可恢复。静态画廊的功能不依赖额外账户。

## 9. 字体、生图与继续加工

### 9.1 字体

登记准确字体家族/变体、版本、来源、许可位置、实际文件和项目用途；对变量字体保留使用的轴值。字体候选名单只是发现入口，不成为个人风格事实。

若生成网页子集或其他转换：

- 源资产与衍生产物分别有 ID/摘要，产物指回源版本。
- 保存已有生产脚本或可复现步骤、字符输入的来源和字重/轴等必要参数。
- 标题变更或内容扩展应触发对字符输入的重查；不能继续使用只覆盖旧标题的文件而不知情。
- 静态题字、完整正文和不断增长的内容可以采用不同覆盖策略。实施者依据目标内容选择合理分段、子集或完整字体，而不规定所有中文站统一方案。
- 在实际页面检查字体加载、缺字/回退、标点、混排、长文本与网络载荷。仅调用一个字体 API 或看到 family 名称不代表字形覆盖得到证实。

库的初始交付必须含实际可取得且条款允许相应用途的中文文件与已渲染样张。字体角色由现场效果决定；不能把候选中某款有性格的字体直接推广为所有长正文默认。

### 9.2 图像及其他材料

原图、透明版本、裁切、压缩和响应式导出保留来源关系。改变布局时能够回到原物，修改边缘、裁切或画幅。程序图形保留可编辑代码、参数和导出入口；动作/声音保留实际播放条件，不能只记一个形容词。

### 9.3 生图接入已有能力

FC 使用宿主当前已安装、已授权的图像生成能力；不规定模型或付费方式，不把人工跨窗口传提示词作为默认协议。没有相应能力时先完成可做部分，交代具体缺口。

代理应从当前设计问题生成素材 brief，最少明确：

- 用在哪里、承担什么作用、画面中需留出什么空间。
- 媒介/材料、构图、色彩关系；风格参考与构图参考分别指向实际原物。
- 需要的画幅、尺寸、透明背景或边缘处理；是否需要成套的一致对象。
- 如何进入实际页面检验，哪一项不确定值得通过一张样张试出来。

例如“标题旁的窄幅黑白植物印痕，边缘留空，不包含正文文字，用于对比细题字和大留白”比“高级东方风”更可操作。此例是 brief 示意，不是已生成资产。

生成后登记实际输出、输入参考、提示/关键参数（工具可提供时）及生产变体，并在真实布局中查看。概念图、风格样张、构图参考与最终资产保留各自角色；prompt 不能代替丢失的图片，生成整页概念图不能代替可用前端。

### 10.2 记忆怎样变成更少的重复工作

每次有用的制作应留下可继续的东西：准确材料、采用位置、可回看的实例，以及按已有规则值得保留的反馈。再次遇到相关问题，代理先解析这些对象，再根据当前内容决定保留、调整或放弃。

可按当前实际采用、相关问题、适用文字与媒介优先找到条目；引用次数只是使用事实。用户局部赞赏不会使所有配料自动升格为长期偏好，整个方向被否定也不会使一个有用源字体从材料查询中消失。

不建立下载监控、自动扫聊天或每次任务结束强制写案例的守护进程。登记由本来就在制作的代理完成；没有新增有效经验时可以只更新使用事实。

### 10.3 Codex 与其他已配置宿主接续

实施者在实际可用环境检查：当前加载的 FC 入口和修订、明确的私人 context/cases、项目目录入口、材料根绑定，以及一次真实查看和修改。

同机宿主可以指向同一授权目录；跨机器沿既有项目/私人同步传递实际目录与材料，使用相对路径和根别名解析。能查到云端向量不证明本地记录或字体已经同步。

不把安装成功、YAML 存在或人工显式运行一次脚本当作自然调用证据。至少从普通制作请求进入，观察代理实际读取了当前 FC 并打开所需材料。宿主 hooks 可在确有适配能力时增加；V1 不依赖新的 hooks 平台。

尚无法操作第二宿主时，可交付离线可移植性检查并留下确切未验证项。不得把沙盒双目录模拟宣称为两个真实宿主已经接通；本地实施交接需要由具有现场能力的代理完成这一步，不能交给用户收集路径和截图。

功能实现与现场验证分别记录。无法操作另一宿主不阻止提交可移植的 helper，但相关现场验收继续标为 pending；只能宣传已实际重放的宿主路线。V6/V7 涉及的真实接续证据未齐时，不宣布整体完成。

## 11. 取舍与成本边界

本规格集中于前端制作。内容发布、社交平台运营、宣传文案和视频营销不迁入 FC；它们可以消费已制作的视觉材料。

V1 采用静态视图、文件目录、实际作品与现有宿主工具。完整交付包括可用材料和制作接续，不包含收藏社交网络、账户系统、默认媒体上传、新图像向量库、随机风格混搭器或全局偏好重建。

目录与画廊共用辅助工具；作品根据自身表达选择实现和材料。复用基础验证不要求不同作品共享同一表面结构。旧 showcase 保留原位置与证据，不要求为构建新库先改造全部历史 demo。

切片允许分多个实现 PR，并行制作不同独立实例；同一目录写入由协调者合并。任何切片都不能把未做的完整范围降格为可有可无的“后续想法”。只有 V1–V7 有对应完成证据，才可宣布本规格整体实现。

## 13. 可执行验收：开发者做正常工作，用户看结果

| A9 | 并发新增不同项、同 ID 冲突、登记/画廊生成中断 | 不同项重读合并后都在；同 ID 不盲覆写；旧目录和旧输出可读；重试可恢复；幂等不生重复版本 | 单进程成功不证明并发或中断安全 |
| A10 | 正常调用入口、错误/缺媒体/受限工具与不可信元数据，含活动 URL 协议 | 当前 FC 确有调用；缺口具体；未执行来源脚本、不安全链接、越界路径或隐式上传；可完成工作继续；无新用户策展负担 | 通过静态 lint 或测试数增加不等于自然行为与审美提升 |
| A11 | 打开独立 showcase，实际观看与操作，并沿制作说明回到材料和实现 | 作品兑现明确的创作追求；排印、构图、材料或动态的主导关系在真实画面成立；需要的状态与布局完整，可提炼的 slots 有具体依据 | 复杂技术、完整控件或行为覆盖不等于作品有表现力；作者判断不冒充用户认可或自主 FC 效果 |

### 13.1 需要的技术检查

- helper 变更运行现有 Python suite，并为新查询/版本/根解析/写入竞争/恢复等真实边界增加有辨别力测试。
- gallery/实例变更实际浏览检查相应界面和行为；按项目情况使用可重复的浏览器脚本，不能让测试只复制实现常量。
- 字体、图像、窄屏、工作状态和动效在实际渲染中查看。reduced motion 等要求按当前场景落实。
- 双语文档、相对链接、许可路径及 `git diff --check` 同步检查。共享入口保持轻量；按仓库规则使用可用的包校验。

### 13.2 完成证据与剩余判断

实施交付应直接给出可看的正向制作积累、独立 showcase、一个实际项目画廊、完整目标页面，以及两次普通任务接续的证据链接。说明哪一版源码、哪个实际入口已运行、哪些宿主尚未验证。所有条目保持真实的观察和反馈状态。

技术证据回答“东西是否真的被看见、拿到、做进项目并继续用”；视觉审查回答构图、字形、材料、信息组织与使用过程是否达到了具体目标。两种工作都由实施者承担。用户可以自然地喜欢、拒绝或指出新方向，无需为证明 FC 的价值再主持一套研究流程。
